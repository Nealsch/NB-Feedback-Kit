# Support

Thank you for your interest in NB Feedback Kit.

**This project is currently maintained by a single developer in my spare time.** There is no team, no company, and no dedicated support staff behind it. I work on this project because I believe in the mission of giving developers ownership over their feedback infrastructure, but that work happens outside of my other professional and personal commitments.

What this means in practice:

- **I do my best to review issues and contributions promptly**, but response times will vary. A reply might come the same day, or it might take a week or more depending on what else is happening.
- **There is no SLA, guarantee, or warranty** — express or implied. This is open-source software released under the MIT licence.
- **Your patience is appreciated.** If an issue sits unanswered for a while, it is not being ignored — it is waiting for the time needed to give it proper attention.

If those terms work for you, read on. If you need guaranteed response times or dedicated support, this may not be the right tool for your use case — and that is completely okay.

---

## Reporting Bugs

If you've found a bug, please [open a GitHub Issue](https://github.com/Nealsch/nb-feedback-kit/issues/new).

When reporting a bug, include:

- **A clear description** of what went wrong
- **Steps to reproduce** — the more precise, the better
- **Expected behaviour** — what you thought would happen
- **Actual behaviour** — what actually happened
- **Environment details** — OS, browser, Node version, SDK version, Worker runtime
- **Screenshots** if relevant

A well-written bug report with clear reproduction steps is the fastest path to a fix. If I can reproduce the issue, I can usually diagnose it.

## Feature Requests

Have an idea for how to make NB Feedback Kit better?

[Open a GitHub Issue](https://github.com/Nealsch/nb-feedback-kit/issues/new) and describe:

- **The problem** you're trying to solve
- **Your proposed solution** — what you'd like to see
- **Any alternatives** you've considered

Good ideas often lead to great discussions. Even if an idea doesn't make it into the core project, the conversation often reveals something valuable about how people are using the SDK.

## Questions

If you're unsure whether something is a bug, or you have a usage question, please [open a GitHub Issue](https://github.com/Nealsch/nb-feedback-kit/issues/new).

There's no separate forum or chat channel. GitHub Issues are the central place for all project communication — bugs, features, questions, and discussions all live there.

Before opening a new issue, please:

1. **Search existing issues** — your question may already have been answered.
2. **Check the [documentation](docs/)** — especially the [Getting Started](docs/getting-started.md) and [Backend](docs/backend.md) guides.

---

## Security Issues

**Do not report security vulnerabilities through public GitHub Issues.**

Security reports must be made privately so they can be assessed before details are publicly visible. Please see [`SECURITY.md`](SECURITY.md) for responsible disclosure instructions.

## Contributing

Contributions are always welcome — and they genuinely help.

Whether it's a bug fix, a documentation improvement, a new feature, or just a well-written issue report, every contribution makes the project better.

Please read [`CONTRIBUTING.md`](CONTRIBUTING.md) before opening a Pull Request. It covers the development setup, coding standards, testing requirements, and the review process.

## A Note on Scope

This project is intentionally focused. It is feedback infrastructure — not a bug tracker, not a help desk, not a CRM, not a product analytics platform.

If you're looking for a feature that falls outside that scope, it may be better served by a different tool or an integration rather than a core addition. The [POSITIONING.md](POSITIONING.md) document explains what this project is and, importantly, what it is not.
